# 简化治理 Skill 名称与验证规则

- **预期结果**：将两个治理 Skill 重命名为 `impl-gov` 和 `doc-gov`，并让 `impl-gov` 在所有治理粒度下约束测试范围选择。
- **范围**：Skill 目录、名称、界面元数据、交叉引用，以及验证范围规则。
- **非目标**：不改变两套治理体系的其他职责、触发条件或文档模型。
- **设计依据**：每个可验证修改批次默认执行最小充分验证；只有影响证据、仓库规范、用户要求或收口契约要求时才扩大到全量验证。
- **影响位置**：两个 Skill 目录及其内部引用。
- **最小充分验证**：搜索旧名称残留，运行两个 Skill 的结构校验，检查 Git 差异。
- **重新讨论条件**：发现外部安装路径、发布配置或未显式记录的名称依赖。

## 实施结果

- `implementation-governance` 已整体重命名为 `impl-gov`，`docs-governance` 已整体重命名为 `doc-gov`。
- 已同步 `SKILL.md` 名称、目录名、界面展示名、默认提示、交叉引用和项目常驻约束片段。
- `impl-gov` 已增加可验证修改批次、最小充分验证、扩大条件、全量验证说明义务和 CI 边界。
- 旧名称残留搜索、YAML 与目录一致性检查、界面元数据检查及 `git diff --check` 均通过。
- Skill Creator 自带的 `quick_validate.py` 因当前环境缺少 `PyYAML` 未能启动；已使用系统 YAML 解析器完成对应结构检查。
- 未运行全量测试：本次只有 Markdown 与 YAML 结构和名称变更，定向检查已覆盖实际风险。

结论：完成。
