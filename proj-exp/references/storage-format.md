# 项目经验存储格式

仅在初始化、写入、合并、强化、修正或重构经验存储时使用本文件。检索已有经验时按 `memory.md → 主题索引 → 经验卡片` 渐进读取，不必先读本格式。

## 目录结构

默认在仓库根目录维护：

```text
.project-experience/
├── memory.md
├── topics/
│   ├── build.md
│   └── test.md
├── cards/
│   └── exp-build-root-config.md
└── archive/
    └── exp-retired-example.md
```

- `memory.md` 是记忆地图，只包含主题入口和核心经验投影。
- `topics/` 保存主题经验索引。主题按项目实际情况形成，不使用固定分类全集。
- `cards/` 保存候选和正式经验卡片，是活动经验的唯一事实源。
- `archive/` 只保存值得解释其失效原因的旧经验；低价值候选淘汰时不归档。

目录、文件名和链接使用仓库相对路径。经验标识采用稳定、可读的 `exp-简短语义`，只使用小写英文字母、数字和连字符；不要使用容易冲突的纯序号，也不要因标题润色更换标识。

## 记忆地图

保持足够小，使 Agent 可以在任务开始时完整读取。使用以下结构：

```markdown
# 项目经验记忆

## 主题

- [构建与编译](topics/build.md)：编译、依赖解析、生成流程以及本地与 CI 差异。
- [测试环境](topics/test.md)：测试入口、固定配置、隔离与数据准备。

## 核心经验

- [处理子模块构建前先检查根目录配置](cards/exp-build-root-config.md)：子模块并不独立解析全部配置。
```

主题描述只提供宽泛唤起场景。`核心经验` 只投影强化程度为“核心”的简短行动规则；没有核心经验时省略该节。不要在这里堆叠普通经验摘要、证据或历史。

## 主题经验索引

一个主题文件可以采用：

```markdown
# 构建与编译

唤起线索：编译失败、依赖解析、生成顺序、子模块、CI 与本地差异。

## 经验印象

- [exp-build-root-config](../cards/exp-build-root-config.md)｜正式｜强｜子模块构建可能受到根目录配置影响｜线索：配置未生效、子模块、编译失败

## 候选印象

- [exp-build-cache-lock](../cards/exp-build-cache-lock.md)｜候选｜普通｜偶发锁冲突可能来自共享构建缓存｜线索：缓存、文件锁、并行构建
```

- 每条只保存标识、成熟状态、强化程度、一句话印象和少量高辨识线索。
- 正式经验放在“经验印象”，候选放在“候选印象”；某节为空时省略。
- 同一卡片可以链接自多个主题索引，但不得复制卡片正文。
- 优先让强经验和当前更可能相关的印象易于发现，不按创建时间机械排序。
- 修改卡片的印象、状态、强度或线索后，同步所有相关主题索引。

## 经验卡片

使用以下模板；列表值保持简短，正文使用中文：

```markdown
---
id: exp-build-root-config
maturity: established
strength: normal
topics:
  - build
cues:
  - 子模块
  - 配置未生效
  - 编译失败
created: YYYY-MM-DD
last_validated: YYYY-MM-DD
encounters: 1
successful_uses: 0
---

# 子模块构建受根目录配置影响

## 经验印象

子模块构建可能受到根目录配置影响。

## 核心认知

说明高成本探索最终获得的项目事实或有效认知。直接写当前成立的结论，不写调查流水账。

## 行动建议

说明未来遇到相似情况时优先检查、判断、执行或避免什么。

## 适用边界

- 适用：列出必要的环境、模块、版本、现象或前置条件。
- 不适用：列出容易混淆但应采用其他判断的情况。

## 形成依据

说明这项认知为何达到单次显著成本或累计显著成本，不需要记录完整耗时和每次操作。

## 强化证据

- YYYY-MM-DD：记录再次命中、是否实际采用、是否减少探索成本以及新增适用边界。

## 实质修正

- YYYY-MM-DD：仅记录改变核心认知、行动或边界的修正；没有时写“无”。
```

字段取值：

- `maturity`：`candidate`、`established`。失效后改为 `retired` 并移入 `archive/`。
- `strength`：`normal`、`strong`、`core`。候选通常保持 `normal`。
- `topics`：列出所有回忆入口；第一个为主要主题。
- `cues`：使用现象、场景、对象和动作等不同维度的短语，不只保存报错原文。
- `encounters`：能够确认是同一经验的遭遇次数。
- `successful_uses`：实际应用且确认减少了探索成本的次数；仅阅读不增加。
- `last_validated`：最近一次由当前代码、环境或实际应用重新确认的日期，不因普通浏览更新。

候选尚无确定结论时，在“核心认知”中明确写出已证实事实与未知边界，不能把推测包装成结论。若候选只为累计重复摩擦而存在，“形成依据”应简记每次摩擦的共同特征和复现可能。

## 合并规则

先比较核心认知、行动建议和适用边界，再比较表面现象：

- 三者实质相同：合并线索、主题和强化证据，保留一个稳定标识。
- 表面相同但原因或行动不同：分别保留，并在经验印象中明确区分条件。
- 新证据推翻旧结论：修正原卡片；不要把新旧结论伪装成两条都有效的经验。

合并后删除重复的活动卡片和索引链接；若旧标识曾被广泛引用，可以在原位置留下仅指向保留卡片的短重定向说明。

## 失效归档

值得保留的失效卡片移动到 `archive/`，将 `maturity` 改为 `retired`，并在标题后增加：

```markdown
## 失效说明

- 失效日期：YYYY-MM-DD
- 原因：说明由什么代码、环境或认知变化导致失效。
- 替代：有替代经验时链接到新的活动卡片。
```

从 `memory.md` 和所有活动主题索引移除其投影。归档不是默认动作：只保留能够解释历史误导、替代关系，或者曾经达到“强”和“核心”的经验。
