## 局部检查

正常任务范围内可以直接执行局部检查：

```text
目标业务领域
→ 文件级上下游
→ 关联技术模块
→ 模块代码锚点
→ 有明确证据时才扩大的直接依赖
```

局部检查属于完成当前任务所需的正常验证，不等同于全局审计。

## 全局审计授权

Agent 不得自动执行全局文档审计。只能检测信号、提出建议，并等待用户明确授权。不得把“确保一致性”解释成默认读取全部文档或代码。

## 审计信号

- 准备发布重要版本或完成重大里程碑；
- 业务领域或技术模块边界调整；
- 大量文档移动、合并或重命名；
- 发现多个权威来源、断裂关系或无法定位影响范围；
- 用户主动要求全局审计。

不设置默认固定周期。

## 建议格式

```text
审计建议：建议/不建议执行全局文档审计
触发原因：与当前证据直接相关的信号
建议范围：结构审计、语义审计或两者
预期发现：希望验证或排除的问题
额外成本：预计需要扩大的文档和代码范围
需要决定：是否授权执行
```

## 获得授权后的审计

### 结构审计

可以全量检查：

- 文档链接是否有效；
- 文件级上下游是否双向一致；
- 是否存在没有地图入口的孤立当前文档；
- 业务—技术—代码映射是否完整；
- 活动实施契约的状态是否正确；
- 归档契约是否与当前入口隔离。

优先使用文件搜索、链接检查和可复现脚本收集证据，不把所有文件全文同时加载进上下文。

### 语义审计

按授权范围检查：

- 是否存在多个文档独立定义同一事实；
- 业务规则与技术实现语义是否冲突；
- 非权威摘要是否偏离权威来源；
- 归档实施契约或旧 ADR 是否被误当成当前依据；
- 技术模块职责与实际代码边界是否漂移。

语义审计成本较高。即使用户授权全局审计，也应先通过结构和搜索证据缩小需要精读的候选集合。

### 报告结果

区分：

- 已确认问题；
- 需要用户决定的冲突；
- 仅有风险信号但尚未证实的问题；
- 未检查或无法验证的范围。

审计授权只允许检查和报告，不自动授权重构文档、修改业务规则或大范围改写代码。
