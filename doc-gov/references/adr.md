# 维护 ADR

只在记录、更新或取代重要决策时读取。ADR 解释决策理由和历史，不替代当前业务或技术设计。

## 判断是否需要 ADR

存在以下任一情况时创建 ADR：

- 改变长期业务或技术边界；
- 影响多个领域或模块；
- 存在多个合理方案和重要取舍；
- 决策难以撤销或撤销成本高；
- 决策会约束后续设计。

普通、容易撤销的实现细节不创建 ADR。

## 最小结构

```markdown
# ADR：决策名称

## 状态
提议 / 接受 / 已取代

## 背景
## 决策
## 考虑过的方案
## 后果
## 影响范围
## 取代关系
```

只保留实际参与决策的方案。影响范围链接受影响的业务设计、技术设计和实施契约。

ADR 被取代时保留原文，创建新 ADR 并建立双向可发现的取代关系。同步更新受影响的当前设计；不得让当前事实只存在于 ADR 中。
