# 维护常驻治理声明

只在用户要求启用治理、建立或调整本 skill 职责内的文档结构、切换治理类型或更新常驻入口时读取。普通文档操作直接复用上下文中的项目地图，不重新执行本流程。

## 写入前定位

1. 使用上下文已有的 `AGENTS.md` 声明与项目结构；缺失或有变化证据时才补读相关部分。写入时保留所有无关指令，不用过期副本覆盖文件。
2. 沿用用户已决定的治理类型，不因维护入口重新评估。
3. 优先融入已有合适目录，仅建立本次缺失且需要的文档；推荐目录不是实际路径的权威定义。

导航型登记主要目录或组件的职责与入口；已有 README 导航可以保留为详细入口，但不能只写“先读 README 才知道目录”。设计型登记业务设计、技术设计与 ADR 的职责和实际入口。只有缺少本次需要的设计基础文档时才叠加“建立设计文档体系”任务包；不要求建立实施契约或用户场景目录。

## 合并声明

- 导航型使用 [导航型片段](../assets/AGENTS.navigation.fragment.md)。
- 设计型使用 [设计型片段](../assets/AGENTS.design.fragment.md)。
- 替换所有占位符后合并到现有 `AGENTS.md`；导航型按实际组件展开条目，设计型省略本次不需要且尚不存在的入口，不为填满模板创建目录。
- 优先融入现有文档地图，不并列建立重复导航；只更新本 skill 负责的条目。切换类型时替换自身类型与入口声明，保留同一区块中的项目专项入口和其他 skill 条目，不整块覆盖。
- 项目级文档地图包含目录职责、实际入口和读取时机，让 Agent 从常驻上下文即可定位。各领域的详细关系、完整文件清单、正文和维护规则仍留在对应文档或 skill 中。
- 新建、移动或删除稳定入口时同步声明；只改正文不重写导航。上下文中的入口已足够时，不为触发本 skill 重新读取 `AGENTS.md` 或地图。

## 验证

- 没有遗留占位符。
- 所有声明入口真实存在。
- 根 `AGENTS.md` 能直接回答本 skill 所辖文档“在哪里、管什么、何时读”，没有复制详细关系或任务细则。
- 未重复或覆盖其他 skill 管理的入口；未为启用本 skill 创建其职责外的目录。
- 启用治理没有被解释为获得全局审计授权。
