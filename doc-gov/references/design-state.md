# 维护双态设计

只在目标设计已经确认但尚未实现，或实施结束需要收敛设计时读取。未决设想和备选方案不得进入权威正文。

## 区分两种状态

- **当前有效设计**：系统当前实际遵循的设计。
- **目标待生效设计**：已经确认、实施验收后生效的设计。

双态只记录设计状态。决策理由写入 ADR；范围、阶段、进度、迁移步骤和验证结果写入活动实施契约。

按能否完整表达目标语义选择形式：

- 少量独立命题即可完整说明时，使用 `[当前有效]` 与 `[目标·待生效]` 标记。
- 多条规则、流程、职责或模块关系必须组合才能成立时，使用“当前有效设计”和“目标设计｜验收后生效”两个完整区块，并链接活动实施契约。

当前命题和目标命题都必须完整、自洽，不使用删除线或文字差异代替语义。如果 Agent 需要从多处分散标记自行拼装目标状态，改用块级双态。未标记内容始终表示当前有效设计。

## 按任务读取状态

- 分析现状、修复当前缺陷或验证当前行为时，只把当前有效设计作为现状依据。
- 实施关联目标时，同时读取当前状态、目标状态和活动实施契约。
- 处理无关功能时，不得假定目标设计已经实现。

## 收敛状态

- 验收通过后，根据实际实现修正目标设计，删除旧态、迁移说明和双态标记，使目标成为普通当前设计；同步业务—技术—代码映射后再归档契约。
- 实施终止时删除目标态，保留当前有效设计。
- 不得让已结束实施的双态长期残留在权威文档中。
