# 治理项目文档

让治理强度与当前知识关系匹配。默认选择能满足当前需要的最轻形态、局部定位并渐进读取；不要为求稳妥直接扫描全部文档或代码。

## 发现治理类型

治理类型是项目或其局部范围的常驻配置。按以下优先级确定本次行为：

1. **本次用户明确指示**：按指定范围和形态执行；一次导航任务不自动改变项目既有类型。
2. **当前范围的 `AGENTS.md` 声明**：读取 `## 文档治理` 中的 `治理类型`，按“导航型”或“设计型”执行，不重新推断。
3. **没有声明**：仅在用户显式调用本 Skill、要求建立或重构文档治理，或者 `AGENTS.md` 已声明采用但缺少类型时，执行一次浅层检查，提出建议并等待确认。普通 README 文案修改不触发类型确认。

浅层检查只读取用户请求、根 README、根 `AGENTS.md`、顶层目录和文件、各顶层目录的主要文档入口。能通过 frontmatter 或开头简介判断职责时，不读取全文，不扫描代码。信息不足时建议导航型。

提议时只说明建议类型、直接依据、建议入口和需要确认的决定，不预先写文件。用户确认启用后，将类型和实际入口写入当前范围的 `AGENTS.md`。发现既有类型与需求冲突时，只列出直接证据并建议变更，不自动切换。

## 按治理类型读取

### 导航型

只回答“有什么、在哪里、各自做什么”。完整读取 [navigation.md](references/navigation.md)，按其中规则建立或维护项目导航、检查升级证据和写入导航型常驻声明。

不要读取设计型参考，除非用户确认升级。

### 设计型

回答系统如何工作、职责如何协作、事实由谁权威定义以及修改会影响哪里。完整读取 [design-workflow.md](references/design-workflow.md)，再按任务渐进读取：

- 建立或重构设计体系：完整读取 [model.md](references/model.md)。
- 局部设计、代码同步或 ADR：只读取 `model.md` 中与任务相关的章节。
- 全局设计文档审计：读取 [audit.md](references/audit.md)；没有用户明确授权时，只检测信号并提出建议。

## 维护常驻声明

- 导航型使用 [AGENTS.navigation.fragment.md](assets/AGENTS.navigation.fragment.md)。
- 设计型使用 [AGENTS.design.fragment.md](assets/AGENTS.design.fragment.md)。
- 替换占位符并验证实际入口；保留现有 `AGENTS.md` 的无关指令。
- 切换类型时替换完整的 `## 文档治理` 区块，不叠加两个片段。
- 未经用户要求不修改常驻指令；启用治理不等于获得全局审计授权。

实施契约始终使用 `$impl-gov`。导航型项目存在 ADR 或实施契约不等于需要升级为设计型。
