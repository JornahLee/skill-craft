# 用户场景 guideline

仅在定义、引用或维护可复用的用户实际使用场景时读取。它是业务使用路径的权威来源，不是一次实施的测试清单。

## 位置与导航

直接使用上下文中项目 `AGENTS.md` 已声明的场景入口。已知目标场景时跳过地图；所需场景内容已在上下文中时直接复用。只有缺少目标位置、场景内容或依赖关系时才局部补读。

场景文档由 `impl-gov` 自己安置和维护，与实施目录同级；不放在一次实施的契约目录，也不放在本 skill 的 `references/`。首次创建或调整位置时才读取 [文档组织与常驻入口](documents.md)，将实际入口同步到项目 `AGENTS.md`，不借助其他 skill 定义其目录。

阶段契约、自动化测试和用户验收包链接同一场景或锚点，不复制其权威事实。场景可引用业务设计说明业务含义，但这种引用不转移场景的目录管理职责。

## 定义范围

每个场景以用户目标组织，维护：

- 用户希望完成什么；
- 正常情况下的主要操作路径；
- 用户应看到的系统正向反馈和完成结果；
- 可复用的场景数据、前置状态与准备步骤；
- 对其他场景的依赖或可供复用的后置状态。

场景保持在“功能能否正常使用”的层级。不要为每个接口参数、异常分支、并发冲突或测试替身扩充场景；它们属于阶段契约、工程验证和用户验收包。

## 复用与引用

- 用户场景由项目常驻场景入口定位；同一用户目标只保留一个权威定义。
- 下游能力引用上游场景的标识或链接，并说明所需后置状态，不复制数据准备步骤。例如，召回或历史浏览可以依赖“数据管理：准备并生效日记成果”。
- 阶段契约只声明本次覆盖或改变了哪些场景步骤，并为异常与精确验收补充最小必要内容。
- 用户验收包优先复用场景数据；仅写出当前环境所需的运行入口、数据差异和具体操作。

## 维护边界

正常使用路径、可见反馈、数据资格或跨功能依赖改变时，先更新用户场景 guideline，再同步受影响的阶段契约和验收包。纯实现细节、临时测试数据和一次性故障排查不写入 guideline。
