# 文档组织与常驻入口

仅在首次安置本 skill 的项目文档，或调整目录与 `AGENTS.md` 入口时读取。普通实施、场景引用与状态恢复直接使用上下文已有的项目导航。

## 职责与默认结构

`impl-gov` 管理活动实施文档和实施归档，并复用项目已有的权威用户场景。用户场景是项目长期使用知识，可以位于领域设计或项目选择的其他位置；其内容归属和目录由项目文档治理决定，不由本 skill 建立平行体系。

没有既有合适位置时，默认使用：

```text
docs/
└─ implementation/
   ├─ active/
   │  ├─ index.md
   │  ├─ YYYY-MM-DD-<topic>.md
   │  └─ YYYY-MM-DD-<topic>/
   │     ├─ plan.md
   │     └─ stages/NN-<stage>.md
   └─ archive/
      └─ record.md
```

- 用户场景不放进一次实施的契约目录。直接引用项目现有的领域设计、场景地图或其他权威位置，不要求建立 `docs/user-scenarios/`。
- 活动索引定位当前实施项；轻量实施使用单文件，完整治理使用计划与阶段契约目录。归档保留原实施项形态和时间线。
- 这是默认布局，不是每次运行的创建清单。只创建当前确实需要的文档，不为补齐树形结构创建空场景、空阶段或虚假导航。

## 融入项目

1. 优先使用当前上下文已给出的目录、职责与入口；信息缺失时只补读相关 `AGENTS.md` 声明或局部导航。
2. 复用项目已有的业务、领域或场景位置，明确权威场景入口和实施根。已有位置冲突时提出调整范围，不擅自搬迁或创建第二份权威场景。
3. 按当前任务建立或维护文档；本 skill 其他参考中的相对路径均基于已确定的实际根，不要求改回默认目录。
4. 在获准建立或调整这些文档结构的任务内，同步将实际入口合并到项目根 `AGENTS.md`；保留其他指令和其他 skill 管理的条目。普通读取不自动补建目录或改写常驻指令。

## 常驻文档地图

把下列信息融入项目已有的文档入口区，而非再建一份重复地图。以下为默认布局示例；写入时改为实际路径，尚不存在且本次不需要的条目省略：

```markdown
### 用户场景与实施入口

- 用户场景：`<项目已有的领域设计或场景入口>` — 正常使用路径、可复用数据和跨场景依赖；只登记项目实际权威位置，不创建本 skill 专属入口。
- 活动实施：`docs/implementation/active/index.md` — 当前实施项、状态和下一动作；上下文不足以恢复实施时读取。
- 实施归档：`docs/implementation/archive/record.md` — 已结束实施的结论与证据；追溯历史时读取。
- 以上入口直接用于定位，无需先触发 skill 获取目录。已有上下文足够时不重读 AGENTS.md、地图或索引；需要维护场景、实施和验收规则时使用 $impl-gov。
```

`AGENTS.md` 常驻目录职责、实际入口和读取时机；具体场景、活动状态、完整目录清单与操作规则留在各自权威文档。目录或稳定入口变化时同步更新对应声明；普通内容变化不重写导航。

完成时确认实际路径存在、无模板占位符、无重复入口，且未覆盖其他 skill 的声明。只刷新变更涉及的条目，不为此重新读取整个项目地图。
