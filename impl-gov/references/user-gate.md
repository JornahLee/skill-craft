# 用户关

仅在工程关已经通过，需要向用户交付人工验收或处理其验收反馈时读取。

用户关验证信息表达、操作过程和结果是否符合真实认知与业务含义。自动化测试、Agent 推断或截图看似正确都不能替代用户结论。

Agent 先完成能够完成的环境准备和可复现性检查，再主动提供可直接执行的步骤：

1. **前置条件**：运行入口、环境状态、账号权限和固定验收数据。
2. **逐步操作**：按顺序给出具体动作和确切输入值。
3. **每步预期结果**：说明界面、数据、状态或外部行为的变化。
4. **语义判断点**：指出需要用户依据真实业务认知判断的现象。
5. **反馈方式**：请用户明确回复“通过”，或说明偏差步骤、实际结果和正确业务含义。

多个场景按场景分组并保持最小充分，不要求用户探索未说明的路径。不得把环境搭建、自动化检查或故障排查伪装成人工验收。

用户尚未实际执行并明确反馈结论时：

- 将阶段状态保持为“等待用户验收”。
- 不得代替用户填写通过。
- 不得进入下一阶段或归档。

用户报告实现错误时留在当前阶段修复并重新通过工程关。用户报告设计或语义偏差时暂停实施，回到设计讨论和阶段契约。用户明确通过后更新阶段契约、总体计划和活动索引，再进入下一阶段或收口。
