# 用户关

仅在工程关已经通过，需要自动准备人工验收或处理其验收反馈时读取。

用户关验证信息表达、操作过程和结果是否符合真实认知与业务含义。自动化测试、Agent 推断或截图看似正确都不能替代用户结论。

## 自动准备验收包

工程关通过后，当前未完成方仍是 Agent。Agent 必须在不等待用户指示的情况下，先完成能够完成的环境准备和可复现性检查，再把下列验收包写入当前阶段契约：

1. **场景依据**：链接本阶段引用的权威用户场景 guideline，说明选取的正常使用路径及依赖的可复用场景数据。
2. **前置条件**：运行入口、环境状态、账号权限，以及相对场景 guideline 仍需补充的固定数据。
3. **逐步操作**：按顺序给出具体动作和确切输入值；已由场景 guideline 定义的数据准备只引用，不重复抄写。
4. **每步预期结果**：说明界面、数据、状态或外部行为的变化，包含用户应看到的正向反馈。
5. **语义判断点**：指出需要用户依据真实业务认知判断的现象。
6. **反馈方式**：请用户明确回复“通过”，或说明偏差步骤、实际结果和正确业务含义。

用户场景负责正常使用体验和可复用前置；异常、冲突、精确接口输入及本阶段边界仍由阶段契约和验收包负责。多个场景按场景分组并保持最小充分，不要求用户探索未说明的路径。不得把环境搭建、自动化检查或故障排查伪装成人工验收。

验收包缺少任一项时，将状态保持为“工程关通过，正在准备验收”，继续完成 Agent 可完成的工作；不得请求用户补充“请准备验收包”或提前签收。只有验收包完整后，才更新阶段契约、总体计划和活动索引为“等待用户验收”，并向用户发出一次验收请求。

用户尚未实际执行并明确反馈结论时：

- 将阶段状态保持为“等待用户验收”。
- 不得代替用户填写通过。
- 不得进入下一阶段或归档。

用户报告实现错误时留在当前阶段修复并重新通过工程关。用户报告设计或语义偏差时暂停实施，回到设计讨论和阶段契约。用户明确通过后更新阶段契约、总体计划和活动索引，再进入下一阶段或收口。
