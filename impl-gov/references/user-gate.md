# 用户关

仅在工程关已经通过，需要自动准备人工验收或处理其验收反馈时读取。

用户关验证信息表达、操作过程和结果是否符合真实认知与业务含义。自动化测试、Agent 推断或截图看似正确都不能替代用户结论。

## 自动准备验收包

工程关通过后，当前未完成方仍是 Agent。Agent 必须在不等待用户提醒的情况下，验证真实运行入口、环境配置和数据准备步骤可执行，再把这些用户以后仍需理解的步骤明确写入当前阶段契约；执行过准备不等于可以省略说明。

1. **场景依据**：链接项目中的权威用户场景 guideline；它可以位于领域设计或项目选择的其他位置。说明选取的正常使用路径及依赖的可复用场景数据。
2. **环境准备**：给出用户可执行的运行入口、配置步骤、环境状态和账号权限。Agent 可以预先验证或执行，但不得让用户以后使用系统所需的环境知识变成黑盒。
3. **数据准备**：验收涉及数据时，必须给出具有明确业务语义的具体数据和准备步骤。公共步骤引用场景 guideline；本阶段新增或不同的数据在验收包中写明。不得只写“数据已准备”。
4. **逐步操作**：按顺序给出真实产品入口中的具体动作、系统处理节点和确切输入值；已由场景 guideline 定义的数据准备只引用，不重复抄写。涉及命令时，优先给出平台无关的指令；只有无法避免时才提供 Linux shell 指令，并明确其适用环境。
5. **每步预期结果**：用用户能够理解的业务语义说明界面、数据、状态或外部行为的变化，包含用户应看到的正向反馈；内部 ID、表状态或测试输出不能代替业务结果。
6. **语义判断点**：指出需要用户依据真实业务认知判断的现象。
7. **反馈方式**：请用户明确回复“通过”，或说明偏差步骤、实际结果和正确业务含义。

用户场景负责正常使用体验和可复用前置；异常、冲突、精确接口输入及本阶段边界仍由阶段契约和验收包负责。多个场景按场景分组并保持最小充分，不要求用户探索未说明的路径。不得把自动化检查、测试替身或故障排查伪装成人工验收；环境和数据准备属于真实使用步骤时，必须向用户说明并保留在验收路径中。

验收准备只编排和验证本阶段已经交付的真实入口、项目既有工具及权威场景数据。不得为了满足验收包格式新增仅供验收使用的代码、接口、脚本、页面或夹具。若没有可执行的真实入口，或缺少本阶段范围内应交付的数据准备能力，说明实施缺口并回到相应阶段；若补齐会改变既定范围或用户可见语义，暂停并请求用户决定。

验收包缺少任一项时，将状态保持为“工程关通过，正在准备验收”，继续整理、验证已有真实步骤，或按上面的边界回到实施；不得请求用户代替 Agent 编写验收包，也不得以专用验收开发填补缺口。只有验收包完整后，才更新阶段契约、总体计划和活动索引为“等待用户验收”，并向用户发出一次验收请求。

用户尚未实际执行并明确反馈结论时：

- 将阶段状态保持为“等待用户验收”。
- 不得代替用户填写通过。
- 不得进入下一阶段或归档。

用户报告实现错误时留在当前阶段修复并重新通过工程关。用户报告设计或语义偏差时暂停实施，回到设计讨论和阶段契约。用户明确通过后更新阶段契约、总体计划和活动索引，再进入下一阶段或收口。
