# 契约方向审查

仅在完整治理的总体契约或当前阶段契约定稿后，或需要继续方向审查与纠偏时读取。目标是及早发现大方向错误，避免实施偏离用户目的和设计初衷。

## 自动委派与审查范围

总体契约 `plan.md` 和当前阶段契约定稿后，主 Agent 自动委派 sub agent 独立审查，无需用户提醒。提供契约、相关用户目的以及领域设计、技术设计的具体入口；阶段审查同时提供总体契约。sub agent 按需读取相关原文，不只依赖主 Agent 的总结，也不扫描全部项目文档。

审查围绕三个判断：

- 目标是否跑偏：最终用户结果是否仍回应原本的问题，是否遗漏核心目标或扩展到另一件事。
- 领域理解是否有根本错误：是否误解核心概念、业务关系或关键规则，导致做出来的能力改变业务含义。
- 技术方向是否冲突：实施路线是否违背已确定的架构边界或关键技术决策。

总体契约重点看整体路线和阶段划分；阶段契约重点看本阶段是否沿着总体路线推进。不要逐项检查实现映射、验收步骤、文档完整性或一般实现细节；只有这些内容暴露方向性问题时才提出。不能以个人实现偏好要求改写契约，也不能为消除偏差自行改写用户目的或权威设计。

## 状态与意见

sub agent 在被审查契约的“方向审查”区维护简短记录：审查状态、结论及必要意见。主 Agent 负责修订契约，sub agent 负责更新审查结论；双方避免同时编辑同一区域。不要求版本台账、逐条意见关闭表或固定审查报告模板。

审查期间标记“待审查”或“审查中”，完成后使用：

| 状态 | 含义与处理 |
| --- | --- |
| 未发现方向性偏差 | 可以继续既有流程；不表示所有细节均已验证 |
| 存在方向性偏差 | 指出偏到哪里、依据和影响，以及建议调整的方向；暂停受影响的推进 |
| 关键方向待确认 | 指出足以影响路线判断的不确定性，以及需要补齐的依据或决策；暂停依赖该判断的推进 |

意见只保留需要纠偏或确认的内容，没有方向问题时给出简短结论即可。依据不完整不等于方向错误：已有信息足以判断时正常给出结论，只有缺失信息影响关键方向判断时才标记待确认。

## 纠偏与恢复

能从现有依据确定的问题，由主 Agent 自动修订，再请 sub agent 确认方向是否已经纠正；涉及用户目的或关键设计取舍的未决冲突，向用户呈现具体问题与建议。不把一般细节建议变成推进门槛，也不替代现有设计关、工程关和用户关。

后续只有目标、核心领域理解、总体路线或关键技术决策发生变化时，才重新审查受影响的契约；一般细节补充、排版调整和状态更新不触发复审。审查中断或 sub agent 不可用时记录未完成及原因，恢复后继续委派，不伪写完成结论，也不因恢复本身重复审查。活动索引只反映影响当前推进的状态与下一动作，详细意见留在契约内。
