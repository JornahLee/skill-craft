# 治理粒度评估

仅在新实施项没有有效治理状态、用户显式要求评估，或已有判断满足失效条件时读取。

## 最小取证顺序

1. 从用户请求提取预期用户结果、范围、已知设计依据和风险。
2. 使用当前对话已经提供的代码、文档、错误和调用关系。
3. 关键证据缺失时，只检查直接相关的入口、调用方、测试映射或数据约束。
4. 影响仍无法界定时，说明缺口并逐步扩大检查；不要默认递归扫描整个仓库。

证据足以支持建议后立即停止调查。用户已经明确指定轻量实施或完整治理时，跳过评级，不为证明用户选择而扫描。

## 判断信号

- **语义不确定性**：业务规则、核心概念、状态含义、数据粒度或操作结果存在缺口、歧义或冲突。
- **阶段反馈依赖**：后续实现必须等待用户验证当前结果后才能可靠设计。
- **影响扩散**：错误可能成为多个模块、流程或后续阶段的错误基础。
- **边界复杂度**：无法收敛为一个边界明确、可独立验收的用户结果。
- **数据与可逆性**：涉及真实旧数据、迁移、权限、安全、事务或难以恢复的变化。
- **验收复杂度**：无法通过一次设计确认、一次实施和一次验收闭环获得充分证据。

这些是调查方向，不是硬触发条件，不机械计分。判断完整治理是否能显著降低语义偏差扩大或高成本返工的风险。

## 输出与决策

能够在单一用户结果、明确边界和一次验收闭环内完成时，默认建议轻量实施。没有实质性治理信号时，简短说明并继续，不为形式完整中断用户。

需要建议完整治理或存在实质分歧时，使用：

```text
治理建议：轻量实施 / 完整治理
判断依据：与当前任务直接相关的信号，不超过三项
预期收益：完整治理会防止什么具体偏差或返工
额外成本：需要增加哪些设计确认、阶段文档或验收步骤
需要决定：是否采用完整治理
```

等待用户决定时复用当前对话中的建议和依据，不写入仓库。用户决定并开始实施后，再按 [活动状态](state.md) 创建索引和相应实施文档。用户选择轻量实施后，除非出现此前未知且会实质改变判断的证据，不反复建议升级。
