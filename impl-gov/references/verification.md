# 验证与工程关

仅在选择验证范围、扩大验证或准备判定工程关时读取。

## 迭代验证

将一组语义连贯、能够独立验证的修改视为一个批次。每个批次完成后，根据直接影响、已知调用方和风险类型运行最小充分检查。

| 改动类型 | 默认最小验证 |
| --- | --- |
| 文档、注释、静态说明 | 差异检查；必要时检查链接、术语和格式 |
| 局部文案、布局、样式 | 类型检查或构建；有交互时运行页面单项测试；布局变化时检查截图 |
| 局部领域规则或纯函数 | 受影响模块单元测试；类型检查或构建 |
| 局部服务或用户流程 | 模块测试、成功与失败路径、相关页面单项回归、构建 |
| 共享组件、公共接口 | 已知调用方相关测试、构建；必要时跨模块回归 |
| 存储、迁移、事务、权限、安全、依赖或构建配置 | 专项测试，并按风险扩大到完整单元、集成或页面回归 |

出现共享影响、数据或安全变化、构建或测试配置变化、跨领域累计修改、相邻回归、准备合并发布，或者用户与仓库规范明确要求时，扩大验证范围。影响范围不清楚时先定向检查调用关系、测试映射和项目结构；确实无法界定时才以全量验证兜底，并记录原因。

## 收口验证

- 相关实现稳定后，对最终版本集中执行契约规定的完整检查。
- 最终版本再次发生代码变化后，原工程关结论失效。
- 工程关后的修正先定向验证，稳定后统一重跑收口验证。
- 记录实际命令、覆盖范围和未运行项，不把定向验证称为完整工程关通过。
- 修复失败项后先重跑失败项，只有影响扩大时才扩大测试。

## 工程关

只有同时满足以下条件才通过：

- 收口验证覆盖当前最终版本并通过。
- 关键数据约束和异常路径得到验证。
- 实现符合阶段契约中的语义映射且没有超出范围。
- 运行方式和交付证据可复现。

通过后更新阶段契约、总体计划和活动索引。下一动作是用户验收时，再读取 [用户关](user-gate.md)。
